• Yes. That GTEx__... prefix was added by populate_database.py.

  The relevant logic is in database/src/populate_database.py:858, where it builds:

  standard_name = f"{collection_name}__{tissue}__{gene_set_name}"

  And collection_name defaults to GTEx in the CLI parser at database/src/populate_database.py:1002:

  parser.add_argument(
      '--collection-name',
      default='GTEx',

  So if you ran the loader without --collection-name, the script would prepend GTEx__ to every loaded gene set, 
  including LIGER-derived ones.

  In your example:

  - collection_name became GTEx
  - tissue was inferred from the path as rna_sc_programs
  - gene_set_name came from the GMT entry itself:
    dataset=parietal_epithelial_cell__signature=gene_loadings__program=Factor_10

  That is how you got:
  GTEx__rna_sc_programs__dataset=parietal_epithelial_cell__signature=gene_loadings__program=Factor_10

  So this was done by the loader, not by the LIGER process output.

  If you want, I can patch the script so --collection-name is required instead of defaulting to GTEx, 
  which would prevent this kind of accidental mislabeling.
